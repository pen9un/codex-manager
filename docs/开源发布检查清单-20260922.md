# Codex Manager 开源发布检查清单

核验日期：2026-09-23。本文记录把当前源码放到 GitHub 前需要保留的证据、发布边界和维护动作。它不是对真实账号或所有平台的全面验收声明。

## 已完成

- 根目录已声明 MIT 许可证，内置主题、主题引擎和提示词资源保留各自的来源与许可证文件。
- README 与 `package.json` 的当前版本统一为 `2.0.1`，功能说明以现有源码为准。
- `pnpm run typecheck`、`pnpm run test:ci`、`pnpm run build` 可在隔离环境复现。
- 发布工作流在 Windows x64、macOS Intel / Apple Silicon、Linux x64 上执行锁定依赖安装、测试、类型检查、生产构建和打包；普通提交和 Pull Request 不自动打包。
- CI 测试显式使用 runner 专用临时目录的真实路径，避免短路径或目录别名触发真实路径校验；目录联接和越界保护保持不变。
- `.gitignore` 排除报告、安装包、构建缓存、保险库、认证文件和配置文件；发布安装包应上传到 GitHub Releases，不提交到源码历史。
- GitHub 社区健康文件已补齐：贡献指南、安全报告、行为准则和 Issue 模板。
- README 补充 12 张真实软件页面截图，全部由隔离环境的合成账号、会话、记忆和扩展配置生成，并逐张检查。
- Windows 构建脚本已移至 `scripts/build-windows.bat`；从暂存文件导出的干净目录、不同工作目录调用，依赖安装、242 项测试、类型检查和生产构建通过。首次生成安装器遇到 `spawn EPERM`，保留诊断后重试打包成功；未修改打包逻辑，尚不能确定首次失败原因。

## 当前验证边界

- 当前源码版本是 `2.0.1`。打包目标为 Windows x64 NSIS、macOS x64/arm64 DMG 与 ZIP、Linux x64 AppImage 与 DEB。
- 账号导入、会话/记忆管理、提示词、MCP、Skills、主题、设置和启动路径使用合成或隔离数据完成自动化检查；CI 永远不读取真实账号。
- Windows 真实 Codex 的运行中主题连接已有一条版本化验收记录；不同 Codex 版本、多个任务窗口和外部主题仍需按版本复测。
- macOS/Linux 的自动构建和测试由原生 runner 执行；目标桌面的冷启动、账号与主题行为、安装升级和卸载仍需实机验收。
- 安装器尚未配置数字签名；干净安装、覆盖升级、卸载和跨 Windows 用户的安全存储迁移不属于当前 CI 门禁。
- 用量刷新是兼容端点查询，不执行 OAuth 令牌续期；账号导入成功不代表在线凭据有效。

## 发布前人工动作

1. 在 GitHub 仓库设置中确认默认分支、Topics、讨论区和私密漏洞报告入口。
2. 更新版本并提交，在 Actions 手动运行“发布 Release”（也支持推送匹配的 `v` 标签），查看多平台构建和自动发布结果；安装包和 `SHA256SUMS.txt` 由工作流上传，不要把 `releases/` 或 `reports/` 目录整体提交。
3. 用测试账号完成安装、升级、卸载、托盘、开机启动、账号切换、主题应用/恢复和配置备份回滚；保存可公开的结果摘要。
4. 逐项复核第三方资源许可证、NOTICE 和上游固定提交，发现授权不清的素材不要随包发布。
5. 发布说明明确列出版本、平台、校验值、已知限制和回滚方式，不把隔离测试描述成所有用户环境都通过。

## 不应进入公开仓库

真实 `auth.json`、`config.toml`、`accounts.vault`、主题备份、会话正文、完整诊断日志、个人路径截图、临时安装器、构建缓存、历史参考镜像和包含令牌的导出文件。
