# GitHub 发布指南

## 仓库边界

Git 根目录为内层 `codex-manager/`，远程仓库为 https://github.com/pen9un/codex-manager 。外层工作目录中的 `data/`、`prompt/`、`references/` 不属于本仓库，不能复制或添加进仓库。

## 提交范围

| 文件或目录 | 处理 | 原因 |
| --- | --- | --- |
| `src/`、`resources/` | 提交 | 应用源码、内置主题、图标及第三方声明 |
| `test/`、`tests/` | 提交 | 两个目录均有实际执行的测试，不能只上传其中一个 |
| `scripts/` | 提交，但排除 `live-smoke.cjs` 和缓存 | 保留构建、资源制作和验证工具；旧诊断脚本会改写真账号数据 |
| `package.json`、`pnpm-lock.yaml`、TypeScript/Electron 配置 | 提交 | 保证安装、类型检查、构建和打包可复现 |
| `.github/`、`.gitignore`、`.gitattributes`、`README.md`、`LICENSE` | 提交 | CI、协作规范和仓库入口 |
| `docs/theme-gallery/` | 完整提交 | HTML 和 520 张配套截图必须一起发布；为隔离示例页面 |
| `docs/images/` | 提交 | README 的 12 张合成数据软件截图，由 `tests/readme_screenshots.cjs` 生成 |
| 开源发布检查清单、本指南 | 提交 | 公开维护说明 |
| 其他 `docs/` 文档 | 本地保留、忽略 | 历史方案、任务记录和机器路径不作为公开使用说明 |
| `assets/` | 本地保留、忽略 | 原始绘画及历史素材；运行资源已在 `resources/` |
| `reports/` | 本地保留、忽略 | 内部日志、验收截图和本机证据 |
| `node_modules/`、`out/`、`dist/`、缓存 | 忽略 | 通过依赖安装和构建生成 |
| `releases/` | 忽略 | 安装包通过 GitHub Releases 分发，不进入 Git 历史 |
| 保险库、认证/配置、环境文件、备份、私钥、数据库 | 忽略并检查暂存区 | 不公开真实凭据和用户数据 |

`.gitignore` 仅影响未跟踪文件，不会自动移除已提交的文件。每次提交前必须检查暂存清单。允许列表中的新文档应同步调整忽略规则；不要使用 `git add -f .`。

## 验证与提交

在内层仓库根目录执行：

```powershell
git rev-parse --show-toplevel
git remote -v
git status --short
pnpm install --frozen-lockfile
pnpm run test:ci
pnpm run build
pnpm exec electron tests/app_startup.cjs
```

暂存前核对文件清单，暂存后再次检查：

```powershell
git ls-files --others --exclude-standard
git diff --cached --stat
git diff --cached --name-only
```

验证通过再提交和推送；不要强制推送覆盖已有远程历史。普通提交不会自动运行构建。发布时手动运行“发布 Release”，并在 Actions 查看对应执行结果；工作流文件已提交不代表发布已成功。

## 跨平台构建

普通代码推送和 Pull Request 不触发构建。独立的 `ci.yml` 已移除；手动运行“发布 Release”或推送版本标签时，由发布流程调用 `.github/workflows/build.yml`：

| 环境 | 架构 | 产物 |
| --- | --- | --- |
| `windows-latest` | x64 | NSIS EXE |
| `macos-15-intel` | x64 | DMG、ZIP |
| `macos-15` | arm64 | DMG、ZIP |
| `ubuntu-24.04` | x64 | AppImage、DEB |

每个环境先安装锁定依赖、运行测试、类型检查及构建，再打包。测试临时目录统一解析为真实路径，避免 Windows 短路径或 macOS 目录别名干扰严格路径检查。平台专属测试只在适用系统上运行。

构建成功后，在 Actions 运行页的 Artifacts 中下载单平台 `packages-*` 或完整 `release-bundle`；后者包含 7 个安装包和 `SHA256SUMS.txt`，保留 7 天。构建阶段只有仓库读取权限；后续发布任务会自动将完整附件上传到 Releases 并公开。

本地在对应系统上执行 `pnpm run build:win`、`pnpm run build:mac`、`pnpm run build:linux`。macOS 默认构建本机架构；需要指定架构时，先 `pnpm run build`，再执行 `pnpm exec electron-builder --mac --x64 --publish never` 或 `--arm64`。

Windows 完整构建脚本仍可使用：

```powershell
cmd /c scripts\build-windows.bat
Get-FileHash .\releases\Codex-Manager-2.0.1-Windows-x64.exe -Algorithm SHA256
```

脚本自动切换至项目根目录；不强制覆盖 `ELECTRON_MIRROR`，需要镜像时由调用环境设置。本地构建入口统一使用 `--publish never`，不会意外上传。

## 发布 Release

### 手动发布：无需提前创建标签

1. 将目标版本代码推送至 `main`，确认 `package.json` 中的版本号正确。
2. 打开 [Actions → 发布 Release](https://github.com/pen9un/codex-manager/actions/workflows/release.yml)。
3. 点击右上方 **Run workflow**，选择分支 `main`，再点击绿色的 **Run workflow**。
4. 工作流读取本次提交的版本号，执行四平台测试、构建和附件汇总；全部成功后创建对应的 `v版本号` 标签、上传附件并公开 Release。

手动发布不要求预先推送标签。若已有同名标签，必须指向本次构建提交；不匹配时应更新版本号后重新发布。首次发布当前 `2.0.1` 可直接运行，后续版本先修改 `package.json` 并提交。已公开的版本不允许覆盖。

如果没有看到按钮，请确认已登录具有仓库写权限的账号，打开的是 **发布 Release**，并刷新页面。手动触发配置需要存在于默认分支；本仓库已在 `main` 配置 `workflow_dispatch`。`build.yml` 是内部复用流程，无需单独运行。

### 推送标签触发发布

1. 更新 `package.json` 的版本号，同步 README 版本徽章。可使用 `pnpm version 2.0.2 --no-git-tag-version` 修改版本，示例版本应替换为实际目标版本。
2. 完成测试并提交版本修改，将提交推送至 `main`。
3. 在该提交创建匹配的标签，例如 `git tag v2.0.2`，再执行 `git push origin v2.0.2`。
4. 在 Actions 查看“发布 Release”运行结果。标签不匹配版本号会在构建前失败。
5. 所有平台成功后，工作流才汇总附件、生成 SHA-256 和中文下载说明，再创建草稿、上传附件并公开发布。GitHub 自动生成的变更记录会附在说明中。

标签支持 `v主版本.次版本.修订号` 和预发布后缀，例如 `v2.1.0-beta.1`；不使用带前导零或构建元数据的版本。预发布版自动设置为 GitHub Prerelease。普通提交不会创建正式版或预发布版。

只在最终发布任务授予 `contents: write`，使用临时 `GITHUB_TOKEN`；无需额外 PAT。不要将发布令牌写入源码或为 Pull Request 增加写权限。

### 失败与重试

- 测试、构建、安装包缺失或摘要生成失败：发布任务不执行，可在 Actions 修复后重跑失败任务。
- 附件上传失败：Release 保留为草稿；重跑时重新上传已验证附件，成功后公开。
- 相同版本已经公开：工作流拒绝覆盖。需要修改源码或重新构建时使用新的版本号和标签，不强推旧标签。
- 仅需本地验证时：运行 `pnpm run test:ci`、`pnpm run build`，需要安装包时执行对应系统的 `pnpm run build:win`、`build:mac` 或 `build:linux`；这些本地入口不会发布。网页的“发布 Release”入口用于正式执行发版流程。

### 校验下载文件

Windows 可用 `Get-FileHash <安装包> -Algorithm SHA256` 与清单比对；Linux 在附件所在目录运行 `sha256sum -c SHA256SUMS.txt`；macOS 使用 `shasum -a 256 -c SHA256SUMS.txt`。全量检查需要清单中的所有文件；只下载一个平台时，可单独计算该文件摘要并与对应条目比较。

### 签名与验证边界

当前 Windows 安装器未配置开发者证书；macOS 使用 ad-hoc 签名，未配置 Apple Developer ID 或公证。后续接入证书时应使用 GitHub Secrets 单独配置，不应提交证书、私钥或密码。Linux 的桌面集成、密钥环和 AppImage 运行依赖仍需在目标发行版验收。

本流程负责源码验证、原生打包和 GitHub Release 发布，不实现应用内自动更新，也不代表所有平台的账号切换、主题连接、安装升级和卸载均已实机验证。
